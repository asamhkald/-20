# خطة الحفاظ على المشروع والبيانات

## الحالة الحالية
الأرشيف الأصلي المرفوع محفوظ كما هو في `legacy/شام-محاسبه-original.zip`. يحتوي على index.html وmanifest.json وsw.js وicon.svg فقط.

## ممنوعات قبل الفحص
- لا تغيّر جداول Supabase الحالية.
- لا تحذف أو تعيد تسمية أعمدة.
- لا تعِد ترقيم المعرفات.
- لا تشغّل سكربت ترحيل على الإنتاج.
- لا تستخدم service_role في المتصفح.
- لا تستبدل النسخة القديمة قبل نجاح المقارنة والقبول.

## بوابات الانتقال
1. احصل على schema-only SQL dump، سياسات RLS، الدوال والمشغلات، وإصدارات migrations.
2. خذ نسخة احتياطية قابلة للاستعادة واختبر استعادتها على مشروع منفصل.
3. أنشئ data dictionary للجداول والأعمدة والعلاقات.
4. اربط كل مفهوم قديم بمفهوم جديد (mapping) وحدد الحقول غير القابلة للتحويل.
5. أنشئ بيئة staging معزولة.
6. نفذ ترحيلات additive فقط أولاً، دون حذف أو تغيير دلالات الأعمدة القديمة.
7. نفذ backfill قابلاً لإعادة التشغيل مع سجل تقدم وقياسات.
8. طابق الأعداد والأرصدة ومجاميع العملات والعلاقات.
9. اختبر سيناريوهات الاستخدام القديمة والجديدة.
10. نفذ cutover بخطة رجوع واضحة وبعد موافقة مالك النظام.

## بوابة قبول البيانات
- عدد السجلات قبل/بعد لكل جدول.
- مجموع الأرصدة حسب الحساب والعملة والفرع.
- توازن القيود.
- عدد الفواتير والدفعات والديون المفتوحة.
- سلامة العلاقات وعدم وجود orphan records.
- نتيجة اختبار استعادة النسخة الاحتياطية.

لا يمكن ضمان الحفاظ على البيانات بمجرد نسخ الواجهة؛ يجب فحص قاعدة البيانات الفعلية.
